## Corrected findings

1. The workspace contained a malformed/redundant package reference. It now
   contains only the canonical Xcode project reference.
2. Xcode acceptance tests could execute a stale SwiftPM CLI. The unit-test
   target now depends on the Xcode CLI target, and the test resolves the CLI
   beside its active test products before considering other build locations.
3. The UI-test target did not explicitly depend on the app. The dependency is
   now represented in the Xcode target graph.
4. Local Debug UI tests could not launch without an installed development
   identity. App and UI-test Debug targets now use local ad-hoc signing.
5. Sidebar navigation tests depended on accessibility behavior that flattened
   complex SwiftUI containers. Each feature heading now exposes a stable,
   module-specific identifier.
6. macOS could restore an “all windows closed” state and launch only the menu
   bar. Scene restoration is disabled for the single control window, making
   GUI launch deterministic without affecting Core configuration persistence.
7. `DashboardServer.start()` mutated a captured error variable from a
   Network.framework callback. A synchronized result object now transfers the
   asynchronous bind failure without a Swift concurrency warning.
8. Xcode's recovered-reference group was removed and source/test references
   were returned to their owning groups.
